# Отгулы, доступы и интеграция corp-mock

## T4. Отгул и отпуск

Сервис возвращает тестовые правила и собственные заявки через MCP. Черновик
создаётся после проверки формата дат, порядка, срока подачи, максимальной
длительности и назначенного руководителя. Для расчёта срока используется
текущая дата в Europe/Moscow, период включает обе даты.

### Сценарий. Период за пределами правил

- WHEN сотрудник запрашивает отсутствие в прошлом, с недостаточным сроком уведомления или слишком надолго
- THEN MCP возвращает ошибку `validation` и запись не создаётся

## T5. Связь MCP и REST

MCP сохраняет черновик в PostgreSQL. core-api отправляет или отменяет этот
черновик через REST с JWT владельца. Ключ создания привязан к пользователю,
команде и типу заявки. Ключ отправки привязан к заявке.

### Сценарий. Повтор и перезапуск

- WHEN несколько вызовов MCP одновременно создают черновик с одним ключом
- THEN сохраняется одна заявка
- AND после перезапуска повтор возвращает её идентификатор

## T6. Рабочие доступы

Список показывает обязательные системы команды и существующие доступы.
Отправка переводит доступ в `pending`. Согласованная заявка остаётся в этом
состоянии до фактической выдачи. Черновик и отменённая заявка не выдают доступ.

### Сценарий. Повторный запрос доступа

- WHEN пользователь запрашивает разрешённую систему повторно до отправки
- THEN возвращается его существующий черновик
- AND новая заявка для уже выданного или ожидающего доступа отклоняется
