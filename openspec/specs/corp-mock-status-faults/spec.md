# Согласование, выдача доступа и управляемые сбои

## T7. Результат согласования

Назначенный руководитель согласует отправленную заявку через контракт D.
Для заявки на доступ `approved` и `fulfilled_at` сохраняются одной транзакцией.
MCP возвращает состояние `granted`, а core-api обновляет карточку, задачу и уведомления.
Для существующей записи `approved` без даты выдачи тот же руководитель может завершить выдачу повторным согласованием.

### Сценарий. Согласование доступа

- WHEN руководитель согласует заявку на разрешённую систему
- THEN REST возвращает `approved` и дату фактической выдачи
- AND MCP показывает `granted`, а после чтения адаптации core-api завершает связанную задачу

## T8. Сбой REST-операции

Тестовый маршрут включается отдельным токеном. Он задаёт один сценарий для
конкретной заявки и операции. Только запрос с правом на операцию может его
израсходовать. Поддерживаются задержка, `503` перед операцией и закрытие
соединения после успешного изменения заявки.

### Сценарий. Потеря ответа на отправку

- WHEN corp-mock фиксирует отправку и закрывает соединение
- THEN core-api повторно читает заявку и сохраняет результат в карточке
- AND повтор подтверждения возвращает тот же номер заявки
