# Knowledge ingestion and access (K1–K3)

## Scope

Рабочие модули `knowledge-service`: загрузка Markdown из `KB_DIR`, фрагменты по
существующим якорям и ограничение доступа по JWT. Используются без изменений
контракт E, общие типы, `data/kb/` и настройки Compose. Поиск и маршруты контракта E
подключаются в K4–K5 к готовому авторизованному представлению базы.

## Requirement: Validate the entire corpus before publishing it

Загрузчик принимает UTF-8 Markdown с YAML-шапкой из `data/README.md`: `id`, `title`,
`visibility`, `tags`, `updated_at`, `disclaimer`. Имя файла соответствует `id`.
Дата календарно корректна, `visibility` — непустой список правил контракта E.
Неизвестные поля и повторные YAML-ключи отклоняются, чтобы опечатка не меняла права.
Пометка тестовой инструкции обязательна для текущего набора данных хакатона.
Файлы сортируются по пути. Любой некорректный документ отменяет загрузку всей базы;
ошибка содержит относительный путь и причину, но не текст документа.

#### Scenario: Existing repository documents
- WHEN загружается текущий `data/kb/`
- THEN все девять документов проходят проверку и сохраняют исходные метаданные
- AND сериализация документа соответствует `Document` контракта E.

#### Scenario: Invalid document
- WHEN отсутствуют поля, неверна дата, неверен доступ или есть дублирующийся id
- THEN загрузка отклоняется с указанием файла и причины
- AND сервис не объявляет готовность с частично загруженной базой.

#### Scenario: Missing or unsafe source
- WHEN каталог отсутствует, пуст, файл не читается или является символической ссылкой
- THEN загрузка завершается диагностической ошибкой без публикации корпуса.

## Requirement: Keep section identifiers stable

Один фрагмент соответствует одному разделу `## Заголовок {#anchor}`. Его id равен
`<doc_id>#<anchor>`, как в текущих контрактах и fixtures. Заголовок документа `# ...`
до разделов разрешён; содержательный текст без раздела, пустые разделы, неверные
и повторные якоря отклоняются. Заголовки внутри fenced code не разделяют документ.
Вложенные заголовки остаются частью раздела. Якорь хранится отдельно от заголовка.
Текст документа без YAML-шапки сохраняется; каждый фрагмент связан с документом,
разделом и точным диапазоном строк исходного тела Markdown.

#### Scenario: Text correction and section reordering
- WHEN меняется текст или порядок разделов, а их якоря сохранены
- THEN идентификаторы соответствующих фрагментов не меняются.

#### Scenario: Invalid section structure
- WHEN отсутствует якорь у раздела, якоря повторяются или раздел пуст
- THEN загрузка отклоняется; потеря текста и перезапись фрагмента исключены.

#### Scenario: Contract source
- WHEN фрагмент сериализуется для результата поиска
- THEN `source` содержит только `doc_id`, `chunk_id`, `title`, `section`
- AND текст, дата, disclaimer и переданный поиском score соответствуют контракту E.

## Requirement: Authenticate before access to any knowledge

Права берутся из проверенного `Authorization: Bearer <JWT>`: алгоритм HS256,
общий `JWT_SECRET`, обязательные `sub`, `login`, `role`, `team_id`, `exp`.
`team_id` может быть null (HR), роль — intern/mentor/manager/hr. Проверяются подпись,
срок, типы и форматы полей. `public` означает доступ авторизованным пользователям.
Настройки не берутся из текста документов, запроса или ответа LLM.

#### Scenario: Invalid authentication
- WHEN токен отсутствует, просрочен, подделан, имеет другой алгоритм или неверные поля
- THEN доступ отклоняется как `401 unauthorized` без сведений о документе и токене.

#### Scenario: Team and role access
- WHEN стажёр Доставки запрашивает базу
- THEN ему доступны public и team:team_delivery
- AND отсутствуют документы team:team_auto и role:mentor, включая метаданные.
- WHEN наставник Авто запрашивает базу
- THEN ему доступны public, team:team_auto и role:mentor.

#### Scenario: Filter before retrieval
- WHEN потребитель запрашивает фрагменты через авторизованное представление
- THEN он получает только разрешённые документы и фрагменты для построения поиска
- AND кеш одного пользователя не переиспользует доступ другого.

#### Scenario: Direct identifier access
- WHEN запрашивается существующий запрещённый документ
- THEN результат — `403 forbidden` без текста и метаданных согласно контракту E.
- WHEN документа нет
- THEN результат — `404 not_found`.

## Requirement: Startup and integration

Приложение загружает проверенную базу при старте в `app.extensions['knowledge_base']`.
Отсутствие `JWT_SECRET` — ошибка конфигурации. HTTP-адаптер будущего K5 получает
авторизованное представление через `knowledge_for_request()`; ошибки доступа уже
преобразуются в существующий единый формат ошибок. `/health` сохраняет контракт.
Обновление файлов применяется перезапуском сервиса, как для остальных данных проекта.

#### Scenario: Independent verification
- WHEN запускаются тесты knowledge-service без core-api и агента
- THEN загрузчик, разбиение и ACL проверяются на настоящих файлах и подписанных JWT
- AND документы/источники валидируются по общим схемам и существующим fixtures.
