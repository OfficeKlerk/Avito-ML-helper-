# Knowledge retrieval and API (K4–K7)

## Scope and compatibility

Продолжение K1–K3. Контракты `e_knowledge.yaml` и `common.yaml`, формат JWT,
идентификаторы существующих документов и разделов остаются прежними. Клиент
`agent.app.tools.Tools.search` должен работать с настоящим HTTP-сервисом без изменений.
Поиск читает текущий корпус из `KB_DIR`; нет ответов, привязанных к проверочным запросам.

## Requirement: Rank only authorized chunks

Кандидаты, document frequency и средняя длина вычисляются только по фрагментам
авторизованного `KnowledgeView`. Используется BM25 с положительным IDF, k1=1.5,
b=0.75; стабильный порядок при равных оценках — по chunk_id. `top_k` от 1 до 10.
Русские формы слов нормализуются Snowball, ё/е эквивалентны, регистр не влияет.
Служебные слова исключаются. Заголовок раздела получает больший вес, чем тело;
заголовок документа и теги помогают находить тематические разделы. Итоговая оценка
умножается на покрытие запроса и на (1 + доля слов запроса в заголовке раздела),
чтобы общий тег документа не вытеснял раздел с прямым совпадением по теме.

#### Scenario: Real matching document
- WHEN пользователь спрашивает про отгул, доступ или адаптацию
- THEN поиск ранжирует содержимое разрешённых файлов и возвращает реальные фрагменты.
- AND текст, источник, дата и disclaimer сериализуются по контракту E.

#### Scenario: No supported answer
- WHEN нет значимых совпадений или совпадение покрывает слишком мало смысла запроса
- THEN возвращается `results: []`, без генерации ответа или подстановки общего документа.

#### Scenario: Isolation
- WHEN закрытый документ добавлен или изменён
- THEN выдача и оценки пользователя без доступа не меняются.
- AND поиск и прямое чтение проверяют одну и ту же политику K3.

## Requirement: Serve contract E over HTTP

`POST /v1/search`: обязательный query — непустая строка до 1000 символов;
необязательный top_k — целое 1..10, по умолчанию 5; лишние поля запрещены.
Неверный JSON, типы, Content-Type и значения возвращают 422 в общем формате.
Авторизация выполняется до разбора тела. `GET /v1/documents/{doc_id}` возвращает
полный документ без YAML-шапки, 403 для закрытого и 404 для отсутствующего.
Нет токена, поддельный или просроченный токен — 401. `/health` доступен без JWT.
Ответы с документами и результатами поиска запрещают кеширование через no-store.
Если база недоступна, авторизованный запрос получает 503 без внутренних сведений.

#### Scenario: Existing agent client
- WHEN настоящий клиент Tools.search обращается по HTTP с подписанным JWT
- THEN он получает results по прежней схеме и записывает успешный вызов в trace.
- AND невалидный JWT превращается в существующий ToolError unauthorized.

## Requirement: Expand the synthetic corpus coherently

Добавляются инструкции по выбранным сценариям: статусы заявок на доступ,
подготовка и передача задач при отсутствии, блокеры адаптации, доступы команд.
Все инструкции синтетические, явно помечены и согласованы с существующими
данными и жизненным циклом заявок. Старые источники сохраняются.

## Requirement: Measure quality reproducibly

Размеченные вопросы хранят expected chunk IDs, пользователя, split и ожидание
пустого ответа. Отдельно проверяются запрещённые источники. Набор содержит dev и
holdout, словоформы, парафразы, запросы без ответа и разные области доступа.
Разметка доступна только проверкам, не импортируется рабочим поиском.
Команда evaluation сравнивает обычный лексический BM25 с улучшенным вариантом
на одном корпусе, сохраняет JSON и Markdown с метриками Recall@1/3/5, MRR,
долей корректных пустых ответов, утечками и ошибками по каждому вопросу.
Порог приёмки: Recall@3 >= 0.85, корректные пустые ответы >= 0.9, утечек 0
отдельно на dev и holdout. Результат не объявляется универсальной точностью:
набор малый, синтетический и покрывает выбранные сценарии.

Первый отложенный прогон сохраняется отдельно и не перезаписывается. Если после
его просмотра исправляется поиск, повторный результат на тех же вопросах явно
помечается регрессионным, а не новой независимой оценкой.

#### Scenario: Regression
- WHEN запускаются тесты knowledge-service
- THEN проверяются загрузка, ACL, API, качество и неизменность существующих источников.
- AND результаты совместимы с текущим агентом и общими контрактами.
