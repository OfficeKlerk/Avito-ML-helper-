# AI-buddy — ИИ-наставник для стажёров

Проект команды на хакатоне Hack&Change 2026, кейс Авито «AI-buddy: ИИ-наставник для стажёров».

## Что мы делаем сейчас

Вся команда делает **ML-ядро** по [плану сервисов и задач](docs/team/01_ML_CORE_BACKLOG.md): **36 задач**, четыре сервиса (`agent`, `knowledge-service`, `core-api`, `corp-mock`), общий старт и три последовательные интеграции.

- Работаем по задачам, без распределения на роли: берём задачу по её ID.
- Результат проверяем через API и автоматические тесты. Интерфейс, оформление, презентация и видео сейчас не делаем.
- Пока соседний сервис не готов, работаем с его заглушкой.

| Готово | Осталось в волне 1 |
|---|---|
| **G0.1–G0.4** — контракты, тестовые данные, заглушки, каркас запуска | **K1–K5** — knowledge-service |
| **A1–A5** — агент: API, контекст, ответы без LLM, инструменты, структурированный ответ | **C1–C6** — core-api |
| **A6** (волна 2) — подключение LLM | **T1–T5** — corp-mock |

## Что уже умеет агент

`POST /v1/chat` (контракт B). По умолчанию агент отвечает без LLM:

- **«Что мне делать дальше?»** — следующие шаги адаптации с причинами.
- **Отгул или отпуск** — находит инструкцию в базе знаний (источники в ответе), понимает даты («завтра», «в пятницу», «13 ноября», «с 13 по 15 ноября»), уточняет недостающую дату и создаёт черновик заявки в corp-mock. Заявка уходит на согласование только после подтверждения пользователем — это делает core-api.
- **Остальные вопросы** — говорит, с чем умеет помочь, и даёт контакт из справочника.
- Если сервис не ответил — `status: degraded` и честный текст: черновик не создан, если он не создан.

Сейчас knowledge-service и corp-mock отвечают только на `/health`, поэтому агент с ними работает в упрощённом режиме. Чтобы агент ходил в заглушки, добавь в `.env`:

```
AGENT_KNOWLEDGE_URL=http://stub-knowledge-service:8060
AGENT_MCP_URL=http://stub-corp-mock:8070/mcp
```

Затем запусти `make stubs-up` и `make up`. Пример запроса — в `fixtures/b_agent/chat.json`, спецификации — в [openspec/specs/](openspec/specs/).

### Подключение LLM

Агент работает с любым OpenAI-совместимым API Chat Completions, который поддерживает вызов инструментов (`tools`). Модель пользуется теми же инструментами, что и режим без LLM, и отвечает в том же формате.

| Переменная | Что задаёт |
|---|---|
| `LLM_PROVIDER` | `mock` — без модели (по умолчанию), `openai` — с моделью |
| `LLM_BASE_URL` | Адрес API до `/chat/completions`, например `https://api.openai.com/v1` |
| `LLM_MODEL` | Имя модели у провайдера |
| `LLM_API_KEY` | Ключ, если провайдер его требует. Хранится только в `.env`, в репозиторий не попадает |
| `LLM_TIMEOUT_SECONDS` | Общее время на ответ модели, по умолчанию 25 |
| `LLM_MAX_TOOL_CALLS` | Предел вызовов инструментов за одно сообщение, по умолчанию 5 |

Задай их в `.env` и перезапусти: `make up`. Если модель не отвечает, отвечает ошибкой или время вышло, агент отвечает по правилам со `status: degraded`. Черновик, который модель успела создать, второй раз не создаётся. Если `LLM_PROVIDER=openai`, а `LLM_BASE_URL` или `LLM_MODEL` не заданы, агент не запускается и пишет в лог, чего не хватает. Системный промпт — [agent/prompts/system.md](agent/prompts/system.md).

## Быстрый старт

Нужны только Docker и `make`.

```bash
make up
```

```bash
make smoke
```

`make up` собирает и запускает четыре сервиса и PostgreSQL. `make smoke` дополнительно поднимает заглушки и проходит по сети все примеры контрактов. Остальные команды покажет `make help`.

| Сервис | Адрес | Язык | Контракты |
|---|---|---|---|
| core-api | http://localhost:8080 | Go | A |
| agent | http://localhost:8090 | Python, Flask | B |
| corp-mock | http://localhost:8070 | Go | C (MCP), D |
| knowledge-service | http://localhost:8060 | Python, Flask | E |
| PostgreSQL | localhost:15432 | — | схемы `core` и `corp` |

Порты и настройки меняются в `.env` (пример — [.env.example](.env.example)). Без `.env` всё запускается со значениями по умолчанию и без ключа LLM.

## Тесты

```bash
make test
```

Тесты одного сервиса: `make test-agent`, `make test-knowledge-service`, `make test-core-api`, `make test-corp-mock`. Отчёт о покрытии печатается в конце каждого запуска.

Все данные в проекте синтетические. Тестовые инструкции не являются регламентами Авито.
