# Покрытие прикладного кода (Q1)

Из корня репозитория запустите:

```bash
node integration/run-coverage.mjs
```

Нужны Node.js 22+ и запущенный Docker с Compose. Команда использует тестовые образы репозитория. Для Go поднимается отдельная PostgreSQL с двумя чистыми базами. После прогона удаляется только созданный для него Compose-проект и его том. Ключ LLM не нужен.

В `reports/coverage/ai-buddy-q1-*/` сохраняются исходные профили, результаты Go-тестов и `summary.md` с числом покрытых и измеряемых строк по компонентам. Итог считается как сумма покрытых строк, делённая на сумму измеряемых строк. Если покрытие ровно 80% или ниже, команда возвращает код ошибки. Ошибка тестов или пропуск Go-теста также останавливают прогон.

| Компоненты | Область и метод подсчёта |
|---|---|
| `core-api`, `corp-mock` | Профили `go test -coverpkg=./...` включают внутренние пакеты и точки входа `cmd/`. Диапазоны инструментированных блоков разворачиваются в строки исходника. Пересечения считаются один раз. Пустые строки, строки комментариев `//` и строки только со структурными знаками пропускаются. Строка считается покрытой, если выполнен хотя бы один её блок. Это оценка по диапазонам Go, поэтому строка внутри многострочного выражения наследует состояние блока. |
| `agent`, `knowledge-service` | Покрытые и исполняемые строки из JSON coverage.py для пакетов `app/`. Наборы проверки качества в `evals/` относятся к тестовым инструментам. |
| `web-app` | Поле `lines` отчёта Vitest для `src/`, включая файлы, которые тесты не импортировали. Исключения в конфигурации покрывают тесты, их настройку, декларации окружения и сгенерированную схему API. |

Подсчёт относится к пяти компонентам продукта. Devkit, браузерные сценарии и инструменты интеграционной проверки используются для разработки и тестирования.
