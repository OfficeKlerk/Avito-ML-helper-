# Q2. Права доступа, инъекции и секреты

Из корня репозитория после [установки браузерных зависимостей](01_BROWSER_JOURNEY.md#запуск):

```bash
node integration/browser/run-security.mjs
node integration/browser/run-security.mjs model
```

Второй запуск читает настройки провайдера из локального `.env` и использует его баланс. Стенд поднимается на локальном порту 13042, тестовый REST corp-mock — на 13043. Порты можно задать через `Q2_WEB_PORT` и `Q2_CORP_PORT`. Каждый запуск получает отдельную PostgreSQL, временные серверные секреты и копию синтетической базы знаний с тестовым документом. После проверки контейнеры и тестовая база удаляются. При падении Playwright сохраняет контекст под `reports/q2/`.

| Проверка | Ожидаемый результат |
|---|---|
| Документы двух команд и роли наставника | Свой документ читается. Для другого пользователя сервер возвращает 403 без названия и текста. |
| Изменённые claims JWT и токен без подписи | Сервер возвращает 401. Поля чужого пользователя или роли в теле запроса дают 422. |
| Задачи и история | Изменение общей по ID задачи затрагивает только владельца. Чужой ход отсутствует в списке сообщений. |
| Заявка и уведомление | Core-api возвращает 404 на чтение и отмену чужой карточки, corp-mock возвращает 403. Чужое уведомление отсутствует в списке и не меняется при попытке отметить его прочитанным. |
| Согласование | Стажёр, пользователь другой команды и наставник не могут согласовать заявку. Назначенный руководитель может. |
| Инструкции в документе и сообщении | В ответе нет тестового маркера и утверждения об одобрении, закрытый источник не раскрывается. Новые действия ограничены черновиками. |
| XSS | HTML пользователя остаётся текстом. HTML в документе и ссылка `javascript:` не создают исполняемые элементы. Обычная HTTPS-ссылка остаётся доступной. |
| Секреты | Проверяются ответы, полученные браузером, включая JavaScript, и логи контейнеров после запросов. Для OpenRouter дополнительно проверяется формат ключа в браузерных ответах и точное значение ключа в логах. |

Проверка относится к перечисленным сценариям и к тестовому стенду. JWT пользователя нужен браузеру для авторизованных вызовов и проверяется на отсутствие в серверных логах.
