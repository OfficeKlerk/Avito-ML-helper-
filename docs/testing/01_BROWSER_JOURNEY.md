# I2 — проверка первого пользовательского пути в браузере

Проверка использует интерфейс и API на одном адресе, с четырьмя сервисами и PostgreSQL. Данные берутся из тестового seed. Сценарий отправляет сообщение от тестовой учётной записи, поэтому запускайте его на отдельном локальном стенде.

## Запуск

Из корня репозитория выполните `make test-stack-up`. Команда поднимает отдельный Compose-проект на порту 13000 и использует режим агента по правилам, без внешней LLM. Если запускаете из PowerShell без Make, из корня репозитория выполните следующие команды в новом терминале.

```powershell
$env:WEB_PORT = '13000'
$env:LLM_PROVIDER = 'mock'
docker compose --project-name ai-buddy-local-test --env-file NUL -f docker-compose.yml up -d --build --wait
```

Для теста нужен Node.js 22 или новее. Из корня репозитория установите зависимости и Chromium.

```bash
npm ci --prefix integration/browser
npm exec --prefix integration/browser -- playwright install chromium
npm test --prefix integration/browser
```

По умолчанию тест открывает `http://127.0.0.1:13000`. Для другого локального порта задайте `I2_BASE_URL`. Если Chrome или Edge уже установлен, можно задать `I2_BROWSER_CHANNEL=chrome` или `msedge` и пропустить скачивание Chromium. Для параметров браузера см. [документацию Playwright](https://playwright.dev/docs/browsers#google-chrome--microsoft-edge).

После проверки тестовый проект можно остановить командой `docker compose --project-name ai-buddy-local-test -f docker-compose.yml stop`.

## Что проверяется

1. Анна входит как стажёр команды «Авито Доставка», видит следующий шаг с причиной и статус своей задачи по каналам.
2. Она спрашивает «Во сколько у нас стендап?». Агент отвечает с источником, а ссылка открывает цитируемый раздел с временем и пометкой тестовой инструкции.
3. После возврата в чат и перезагрузки страницы остаются вопрос, ответ и источник.
4. После выхода и входа Максим видит команду «Авто» и свой статус той же задачи. В чате нет вопроса Анны, а прямая ссылка на её командный документ даёт отказ.

## I3 и I4 — отгул и выдача доступа

После установки зависимостей и браузера запустите из корня репозитория:

```bash
npm run test:requests --prefix integration/browser
```

Команда создаёт отдельный Compose-проект с чистой PostgreSQL и агентом в режиме по правилам. Интерфейс доступен на порту 13034. REST API corp-mock доступен на порту 13035 только с этой машины. Он нужен для тестовых переходов от имени руководителя. Если порты заняты, задайте `I34_WEB_PORT` и `I34_CORP_PORT`. Чтобы использовать установленный Chrome или Edge, задайте `I2_BROWSER_CHANNEL`. По окончании команда удаляет контейнеры и тестовую базу созданного проекта.

- **I3.** Стажёр уточняет дату отгула в чате, видит черновик и явно отправляет заявку. Тест сверяет корпоративный номер, перезапускает core-api и corp-mock, повторяет подтверждение с тем же ключом и проверяет сохранённый результат. Затем руководитель отклоняет первую заявку, а стажёр отменяет вторую в интерфейсе.
- **I4.** Стажёр открывает чат из задачи адаптации, запрашивает доступ в пространство команды и подтверждает заявку. До выдачи задача остаётся в работе. После согласования назначенным руководителем corp-mock фиксирует выдачу, а задача и карточка обновляются. Повторы для ожидающего и выданного доступа не создают черновиков. Стажёр другой команды получает отказ на недоступную ему систему и на чтение чужой заявки.

## I5 — проверка с моделью и резервный режим

Заполни `LLM_BASE_URL`, `LLM_MODEL` и `LLM_API_KEY` в локальном `.env` по [инструкции](../../README.md#подключение-llm). Затем запусти из корня:

```bash
npm run test:model --prefix integration/browser
```

Команда создаёт отдельную PostgreSQL с синтетическими данными. Запросы к настроенному провайдеру используют его баланс. Тест проверяет уточнение даты, черновик отгула на указанную дату, отправку и согласование, а также запрос доступа и завершение связанной задачи после фактической выдачи. Ответ в режиме `degraded` приводит к падению живого прогона. Отчёт `reports/i5-playwright-result.json` содержит идентификатор модели и длительности проверенных запросов.

Резервный режим проверяется отдельно управляемыми тестами агента. `make test-agent` включает таймаут HTTP-клиента, переход на правила при сбое модели и сохранение единственного черновика, созданного до сбоя. Эти проверки используют локальную имитацию модели.

Проверенный прогон от 13 ноября 2026 года на базе `81cb020` с GPT-5.4 mini через OpenRouter прошёл в Chrome. От запроса в чате до получения черновика прошло около 4,1 с для отгула и 5,7 с для доступа. Замеры включают браузер, API и инструменты агента. В замер отгула также вошла сверка даты в corp-mock. Оба ответа имели статус `ok`, обе заявки согласованы, выдача доступа обновила задачу адаптации. Отдельный локальный прогон тестов клиента модели и резервного режима дал 59 успешных проверок. Результаты относятся к синтетическим данным и одному живому прогону.

## I6 — восстановление после сбоя отправки

```bash
npm run test:recovery --prefix integration/browser
```

Требования к браузеру, порты и создание отдельного стенда те же, что для I3–I4. Команда включает управление сбоями только в новом локальном проекте, генерирует для него одноразовый токен и удаляет проект с тестовой базой после проверки.

1. Corp-mock отказывает в отправке, затем задерживает её дольше таймаута core-api. После обоих сбоев в интерфейсе остаётся черновик, внешний номер отсутствует, уведомление об отправке не создаётся.
2. Corp-mock сохраняет заявку и обрывает ответ. Core-api считывает сохранённый результат. В интерфейсе появляется номер заявки и ровно одно уведомление об отправке.
3. После перезапуска core-api и corp-mock повтор с прежним ключом возвращает тот же номер. После обновления страницы история чата, карточка и уведомления показывают сохранённое состояние.

JSON-отчёт Playwright с длительностями и HTTP-статусами сохраняется в `reports/i6-playwright-result.json`. Логи контейнеров сохраняются перед остановкой в `reports/i6-recovery/<имя проекта>/compose.log`. Этот прогон использует агента в режиме по правилам. Проверка реальной модели и её резервного режима относится к I5.
